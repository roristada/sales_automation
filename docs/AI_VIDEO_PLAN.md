## 1. เป้าหมาย

จากสินค้าหนึ่งชิ้น ให้ระบบทำได้เกือบอัตโนมัติ:

```
ข้อมูลสินค้า + รูป
→ AI กรอกข้อมูล/ดึงข้อเท็จจริง (คนยืนยัน)
→ AI เขียนสคริปต์ไทย + แผนภาพแต่ละฉาก (คนตรวจ claim)
→ AI สร้างคลิปวิดีโอทีละฉาก (คนดู/อนุมัติ/สร้างใหม่เฉพาะฉาก)
→ Remotion ประกอบ: ทรานซิชัน ซับไทย CTA disclosure (+ เสียงพากย์เมื่อมี TTS)
→ ตรวจไฟล์ (QA) → คนอนุมัติ → ส่งออก/เผยแพร่
```

### หลักที่ไม่เปลี่ยน
- **ไม่จำลองผล:** ไม่มี key/เครดิต → แสดง "ยังไม่ได้ตั้งค่า" ไม่สร้างผลปลอม
- **คนตรวจก่อนเสมอ:** ข้อเท็จจริงจาก AI = "AI ประมาณการ" ใช้ในสคริปต์ไม่ได้จนกว่าจะยืนยัน; claim ทุกข้อต้องตรวจ; ฉาก AI ทุกฉากต้องอนุมัติก่อน render
- **ป้ายตรงความจริง:** แยกให้เห็นชัด "คลิป AI" / "motion graphics จากรูปสินค้า" / "คลิปของคุณ" — ไม่เรียก motion graphics ว่า AI video
- **ไม่แต่งข้อมูล:** ห้าม AI เติมสเปก ตัวเลข รีวิว ยอดขาย ส่วนลด; คนในคลิป AI ห้ามนำเสนอว่าเป็นลูกค้าจริง
- **คุมเงิน:** ประมาณราคาก่อนทุกงานที่เสียเงิน, เพดานต่อวิดีโอ/วัน/เดือน, ยืนยันก่อนเกินเกณฑ์, บันทึกค่าใช้จ่ายจริงจาก OpenRouter (`usage.cost`)

## 3. ทำไม OpenRouter

- key เดียวใช้ทั้ง **โมเดลข้อความ** (เขียนสคริปต์, ดึงข้อมูล), **โมเดลภาพ**, และ **โมเดลวิดีโอ** หลายค่าย — เปลี่ยนรุ่นได้ที่หน้าตั้งค่า ไม่ต้องแก้โค้ด (Veo 3.1 preview บน Gemini API ปิด 2026-10-22 แสดงว่ารุ่นเปลี่ยนเร็ว)
- เติมเครดิตล่วงหน้า = เพดานจริงอีกชั้น; ทุก request คืนค่าใช้จ่ายจริง
- OpenRouter ระบุว่าไม่บวกราคาจากผู้ให้บริการ
- ข้อจำกัด: Gemini Omni Flash ไม่มีใน OpenRouter; เงื่อนไขเชิงพาณิชย์ขึ้นกับผู้ให้บริการแต่ละราย (Google/Kuaishou/ByteDance/…) — ต้องเช็กก่อนใช้รุ่นนั้นจริง; ข้อมูลและรูปสินค้าถูกส่งไปยังผู้ให้บริการของรุ่นที่เลือก

API ที่ใช้ (จาก docs ของ OpenRouter):
- ข้อความ/ภาพเข้า: `POST /api/v1/chat/completions` (รองรับ `response_format` แบบ JSON schema ในรุ่นที่มี `structured_outputs`)
- วิดีโอ: `POST /api/v1/videos` (ได้ job id) → `GET /api/v1/videos/{id}` จน `completed` → `GET /api/v1/videos/{id}/content?index=0`; catalog + ราคา: `GET /api/v1/videos/models`

## 6. การเปลี่ยนแปลงฐานข้อมูล (migration ใหม่ — ใช้ `supabase migration up` เท่านั้น)

| ตาราง/คอลัมน์ | ใช้ทำอะไร |
|---|---|
| `ai_settings` (ต่อผู้ใช้) | โมเดลที่เลือกต่องาน (`script`, `extract`, `scene_prompt`, `review`, `video_product`, `video_lifestyle`), เพดานต่อวิดีโอ, เกณฑ์ที่ต้องยืนยัน |
| `ai_requests` | log ทุกการเรียก OpenRouter: งาน, โมเดล, token/วินาที, ค่าใช้จ่ายจริง, สถานะ, error, อ้างอิงสินค้า/สคริปต์/ฉาก (ใช้คำนวณเพดานและรายงาน) |
| `storyboard_scenes` + คอลัมน์ | `visual_mode` (`product_motion` / `ai_video` / `library`), `visual_prompt`, `camera`, `shot`, `transition`, `reference_asset_ids` |
| `scene_generations` | งานสร้างคลิปต่อฉาก: provider, model, prompt ที่ส่งจริง, รูปอ้างอิง, ความยาว, ราคาประมาณ/จริง, สถานะ (`queued/generating/succeeded/failed/canceled`), สถานะตรวจ (`pending/approved/rejected`), หมายเหตุความแม่นยำของสินค้า, asset ผลลัพธ์, job id ของ OpenRouter |
| `assets` (มีอยู่แล้ว) | เก็บคลิป AI เป็น asset `ai_generated = true`, ที่มา = โมเดล + prompt, สิทธิ์ = ตามเงื่อนไขผู้ให้บริการ |
| `usage_events` (มีอยู่แล้ว) | เพิ่ม provider `openrouter` ใช้กับเพดานรายวัน/เดือนเดิม |

RLS owner-only ทุกตาราง + เคสใน `tests/rls`; worker (service role) เขียนผลการสร้าง

## 7. Milestones (ทำทีละขั้น ทดสอบของจริงทุกขั้น)

### AI-1 ฐาน OpenRouter (ไม่เสียเงิน ยกเว้นทดสอบเชื่อมต่อ ~0.1 บาท) — ✅ เสร็จ 2026-10-22 (ดู CHECKLIST)
- `OPENROUTER_API_KEY` ใน `.env.local` (server/worker เท่านั้น), client กลาง: retry, timeout, ดึง `usage.cost`, ข้อความ error ภาษาไทย
- หน้าตั้งค่า: สถานะ "เชื่อมต่อแล้ว/ยังไม่ได้ตั้งค่า", เครดิตคงเหลือ (ถ้า API ให้), เลือกโมเดลต่องานจาก catalog จริง (เตือนถ้ารุ่นที่เลือกหายไป), เพดานต่อวิดีโอ
- `ai_requests` + รวมเข้ากับ `spend_summary`/เพดานเดิม; ยืนยันก่อนงานที่เกินเกณฑ์
- **Acceptance:** ไม่มี key → ทุกปุ่ม AI แสดงว่ายังไม่ได้ตั้งค่า (ปุ่มคัดลอกคำสั่งแบบเดิมยังใช้ได้); มี key → ทดสอบเรียกจริง 1 ครั้งและเห็นค่าใช้จ่ายใน log

### AI-2 กรอกข้อมูล + เขียนสคริปต์อัตโนมัติ — ✅ เสร็จ 2026-10-22 (ดู CHECKLIST; ใช้ DeepSeek V4.1 Flash เป็นค่าเริ่มต้นตามตาราง §4 แทน Gemini/Sonnet ที่เขียนไว้ด้านล่าง)
- **กรอกข้อมูลอัตโนมัติ:** วางรายละเอียดสินค้า และ/หรือ เลือกรูป (รวมรูปสเปกที่มีตัวหนังสือ เช่น "IP55 Certified") → `gemini-3.8-flash` ตอบเป็น JSON ตาม schema: หมวดหมู่, คำอธิบายสั้น, ข้อเท็จจริง (หัวข้อ, ค่า, มาจากข้อความหรือรูปไหน) → ตรวจตัวเลขกับข้อความต้นทาง (มีอยู่แล้ว) → บันทึกเป็น "AI ประมาณการ" → คนยืนยัน (ปุ่ม ยืนยัน/ยืนยันทั้งหมด มีแล้ว)
- **เขียนสคริปต์อัตโนมัติ:** ปุ่ม "ให้ AI เขียนทั้งสคริปต์" → `claude-sonnet-5.5` ได้ JSON: hook, ฉาก (คำพูด, ข้อความบนจอ, ภาพ), claim ที่อ้างรหัสข้อเท็จจริง, แคปชัน → ผ่าน `validate.ts` เดิม (ห้ามตัวเลขที่ไม่มีข้อเท็จจริงรองรับ, ต้องมี disclosure) → claim ทุกข้อ "รอตรวจ"
- **เทียบโมเดลเขียนสคริปต์** ก่อนเลือกค่าเริ่มต้น: สคริปต์เดียวกันจาก DeepSeek v4.1 Flash / Claude Haiku 5.5 / Qwen 3.8 Flash (+ Sonnet 5.5 เป็นตัวอ้างอิง) → ผู้ใช้อ่านเทียบ (รวมไม่ถึง 2 บาท)
- ปุ่ม "AI ช่วยเขียน" ทีละฉากเรียก API ได้ตรง (เก็บแบบคัดลอกวางไว้เป็นทางสำรอง)
- **Acceptance:** สินค้า Edifier จริง → กรอกข้อมูล+ข้อเท็จจริงจากรายละเอียดและรูป → สคริปต์ครบทุกฉากที่ผ่าน validate หลังคนตรวจ claim; ทดสอบ schema/การปฏิเสธคำตอบที่ผิดรูปแบบด้วย unit test (ไม่จำลองว่าเป็นคำตอบจริง)

### AI-3 สร้างคลิป AI ทีละฉาก + ตรวจ/อนุมัติ — 🚧 โค้ด+เทสเสร็จ 2026-10-22 รอเติมเครดิตเพื่อสร้างคลิปจริง + เทียบ 3 รุ่น (ดู CHECKLIST)

- worker รับงาน `scene_generations` (คิวใน Postgres แบบเดียวกับ render, จำกัดพร้อมกัน 1–2 งาน), ส่งรูปสินค้าเป็นเฟรมแรก, poll สถานะ, ดาวน์โหลดเก็บเป็น asset, บันทึกค่าใช้จ่ายจริง, ลองใหม่เมื่อ error ชั่วคราว
- Video Studio แบบแบ่งฉาก: รายการฉาก (ภาพตัวอย่าง/คลิปจริง, สถานะ, ราคา), แก้ prompt, เลือกรูปอ้างอิง, สร้าง/สร้างใหม่เฉพาะฉาก, อนุมัติ/ไม่ผ่าน, เปลี่ยนเป็นคลิปของคุณหรือ motion graphics, ป้าย "คลิป AI — สินค้าอาจไม่ตรงของจริง 100%"
- เริ่มด้วย **ทดสอบเทียบ 3 รุ่น** (Veo 3.1 Lite / Kling v3.0 std / Veo 3.1 Fast) จากรูป Edifier → ผู้ใช้เลือกค่าเริ่มต้น
- **Acceptance:** สร้างคลิปจริงอย่างน้อย 1 ฉากผ่าน OpenRouter, ดูตัวอย่างได้, สร้างใหม่เฉพาะฉากนั้นได้โดยฉากอื่นไม่ถูกสร้างใหม่, ค่าใช้จ่ายตรงกับที่ OpenRouter รายงาน

### AI-4 ประกอบวิดีโอ (template v3) — ✅ ส่วนหลักเสร็จ 2026-10-22 (ใช้คลิปที่อนุมัติ, บล็อก render, QA, แคปชัน AI) · ยังไม่ทำ: ทรานซิชันต่อฉาก (ดู CHECKLIST)

## 8. ข้อจำกัดและความเสี่ยง

| เรื่อง | การรับมือ |
|---|---|
| AI เปลี่ยนรูปทรง/โลโก้/ปุ่มของสินค้า | ใช้รูปจริงเป็นเฟรมแรก, ฉากที่ต้องเห็นสินค้าชัดใช้รูป/คลิปจริง, คนต้องอนุมัติทุกฉาก, AI ช่วยชี้จุดที่เพี้ยน |
| 3D จริงสร้างจากรูปเดียวไม่ได้ | ไม่ติดตั้ง Blender/Three.js ตอนนี้; "โชว์สินค้าหมุน" = คลิป AI จากรูป ติดป้ายว่าเป็น AI |
| คนในคลิป AI | ห้ามนำเสนอเป็นลูกค้า/รีวิวจริง; ไม่ใช้ใบหน้าคนจริงเป็นอ้างอิง |
| สิทธิ์รูปสินค้าจากร้าน | รูปที่ผู้ใช้ถ่ายเองปลอดภัยที่สุด; เก็บแหล่งที่มาและสิทธิ์ของทุกรูปที่ส่งไปสร้าง |
| เงื่อนไขเชิงพาณิชย์ต่างกันตามผู้ให้บริการ | ตรวจและบันทึกก่อนเปิดใช้รุ่นนั้นเป็นค่าเริ่มต้น |
| ราคา/รุ่นเปลี่ยนเร็ว | ดึง catalog + ราคาจริงก่อนทุกงาน, ใช้ค่าใช้จ่ายจริงจาก response ไม่ใช่ราคาที่จำไว้ |
| ข้อมูลส่งไปผู้ให้บริการหลายประเทศ (DeepSeek/Qwen = จีน, ผ่านผู้ให้บริการที่ OpenRouter เลือก) | ส่งเฉพาะข้อมูลสินค้าสาธารณะ ไม่ส่งข้อมูลบัญชี/รายได้; เลือกผู้ให้บริการได้ในตั้งค่า |
| AI แต่งข้อมูลในสคริปต์ | JSON schema + validate.ts + ตัวเลขต้องมีข้อเท็จจริงรองรับ + คนตรวจ claim |
